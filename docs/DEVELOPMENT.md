# Development Guide

## Процесс разработки

### Спринты

- Один спринт = одна законченная задача.
- Один спринт = один Pull Request (или один коммит, если работа ведётся без PR).
- После каждого пятого спринта проводится архитектурное ревью (без нового функционала).

### Порядок работы

1. **Сначала архитектура, потом код.** Прежде чем писать код, определи:
   - какие новые сущности появляются;
   - как они связаны с существующими;
   - в какие файлы будут внесены изменения.
2. Любое изменение должно сохранять проект в рабочем состоянии. Нельзя оставлять сломанный код "на потом".
3. Не допускаются большие рефакторинги одновременно с добавлением нового функционала. Либо рефакторинг, либо фича — не вместе.
4. **План всегда строится до выполнения.** Execution Planner составляет последовательность действий до того, как любой провайдер начнёт работу.
5. **Любая внешняя зависимость — через Provider Framework.** LLM, MCP, Git, RAG, файловая система, Docker, PostgreSQL — всё подключается только через Provider Framework. Прямые импорты внешних сервисов в ядро Programming Engine запрещены.
6. **Единый ExecutionContext.** Все этапы pipeline работают через ExecutionContext. Ни один этап не хранит состояние выполнения самостоятельно.
7. **Providers не получают данные самостоятельно.** Любые данные сначала собираются ContextCollector. Provider работает исключительно с ExecutionContext. Новые Provider не должны обращаться напрямую к БД.

### Архитектурный спринт

Каждый пятый спринт — архитектурный. Он не добавляет новый функционал. В него входят:
- рефакторинг;
- документация;
- устранение технического долга;
- ADR для ключевых решений.

### ADR

Любое архитектурное решение, которое затрагивает более одного модуля или меняет контракт между компонентами, должно быть задокументировано в ADR (Architecture Decision Record).

ADR хранятся в `docs/architecture/decisions/`.

## Code Style

- Следовать существующим конвенциям кодовой базы.
- Новый модуль = новая директория в `services/`.
- Экспорт модуля всегда: `module.exports = new Service();` (синглтон) + именованные экспорты классов.
- API-эндпоинты регистрируются в корневом `index.js`.
- Авторизация — через `requireAuth` из `middleware/auth`.
