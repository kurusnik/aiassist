# Управление паролями в админ-панели

## Обзор
Система безопасного изменения паролей с валидацией, лимитом попыток и логированием для админ-панели AI Assistant.

## Компоненты системы

### 1. База данных
- **Таблица `password_change_logs`** - логи всех попыток изменения пароля
- **Таблица `password_change_attempts`** - отслеживание лимита попыток
- **Поля в таблице `users`**:
  - `two_factor_enabled` - включена ли двухфакторная аутентификация
  - `two_factor_secret` - секрет для 2FA
  - `password_changed_at` - время последнего изменения пароля

### 2. Модуль PasswordManager
Расположен в `services/passwordManager.js`, предоставляет:
- Валидация пароля (длина, сложность)
- Проверка лимита попыток
- Верификация текущего пароля
- Хеширование нового пароля
- Логирование операций

### 3. API эндпоинты

#### Для пользователей:
- `PUT /api/change-password` - изменить собственный пароль

#### Для администраторов:
- `PUT /api/admin/users/:id/change-password` - изменить пароль пользователя
- `GET /api/admin/users/:id/info` - информация о пользователе
- `GET /api/admin/users/:id/password-logs` - логи изменения пароля
- `GET /api/password-change/rate-limit` - проверка лимитов

### 4. Интерфейс админ-панели
Новая вкладка "Пароли" в `/admin.html` с разделами:
- Изменение собственного пароля
- Изменение пароля других пользователей
- Просмотр логов изменения паролей

## Требования к паролю

### Основные правила:
1. **Минимальная длина:** 8 символов
2. **Максимальная длина:** 100 символов
3. **Обязательные символы:**
   - Буквы верхнего регистра (A-Z)
   - Буквы нижнего регистра (a-z)
   - Цифры (0-9)

### Рекомендации:
1. **Специальные символы:** ! @ # $ % ^ & * ( ) _ + - = [ ] { } ; ' : " \ | , . < > / ?
2. **Запрещенные пароли:** Не использовать распространенные пароли (password, 12345678 и т.д.)
3. **История паролей:** Новый пароль не должен совпадать с текущим

## Лимит попыток

### Настройки безопасности:
- **Максимальное количество попыток:** 5
- **Временное окно:** 15 минут
- **Автоматический сброс:** После успешного изменения пароля или по истечении времени

### Логирование:
Все попытки изменения пароля логируются с указанием:
- ID пользователя
- ID администратора (если применимо)
- IP адрес
- User Agent
- Статус (успех/ошибка)
- Сообщение об ошибке
- Временная метка

## Двухфакторная аутентификация

### Текущая реализация:
- **Поле для будущей реализации:** `two_factor_enabled`
- **Опциональная проверка:** Параметр `requireTwoFactor` в API
- **Заглушка:** На данный момент возвращает сообщение о необходимости реализации

### Планы на будущее:
1. Интеграция с TOTP (Time-based One-Time Password)
2. Поддержка приложений-аутентификаторов
3. Резервные коды для восстановления

## Меры безопасности

### 1. Защита от брутфорса:
- Лимит попыток изменения пароля
- Блокировка после превышения лимита
- Автоматический сброс через 15 минут

### 2. Защита данных:
- Пароли никогда не хранятся в открытом виде
- Использование bcrypt с солью
- Минимальная стоимость хеширования: 10 раундов (рекомендуется 12)

### 3. Аудит и мониторинг:
- Полное логирование всех операций
- Отслеживание IP адресов
- Уведомления администратора о подозрительной активности

## Использование

### Для пользователей:

```javascript
// Изменить собственный пароль
fetch('/api/change-password', {
  method: 'PUT',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    currentPassword: 'старый_пароль',
    newPassword: 'новый_пароль',
    confirmPassword: 'новый_пароль'
  })
});
```

### Для администраторов:

```javascript
// Изменить пароль пользователя
fetch('/api/admin/users/123/change-password', {
  method: 'PUT',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    newPassword: 'новый_пароль_пользователя',
    confirmPassword: 'новый_пароль_пользователя',
    requireTwoFactor: false
  })
});
```

## Безопасность

### Критические моменты:
1. **Никогда не логировать пароли** даже в хешированном виде
2. **Валидировать входные данные** на стороне сервера
3. **Использовать HTTPS** в production среде
4. **Ограничивать доступ** к API авторизацией
5. **Регулярно обновлять зависимости** (особенно bcrypt)

### Рекомендации по развертыванию:
1. Настроить правильные переменные окружения
2. Использовать отдельную базу данных для production
3. Включить SSL/TLS для всех соединений
4. Регулярно делать резервные копии логов
5. Мониторить подозрительную активность

## Поддержка

### Проблемы и решения:

#### Проблема: "Слишком много попыток"
**Решение:** Подождать 15 минут или обратиться к администратору

#### Проблема: "Пароль не соответствует требованиям"
**Решение:** Следовать правилам сложности пароля

#### Проблема: "Неверный текущий пароль"
**Решение:** Проверить введенный текущий пароль

#### Проблема: "Логи не отображаются"
**Решение:** Проверить выполнение миграций и права доступа
