# ADR 008: Execution Pipeline — оркестратор выполнения

**Status:** Accepted

## Context

Programming Engine имеет ExecutionPlan (последовательность шагов), ProviderManager (реестр провайдеров) и ExecutionContext (контейнер состояния). Отсутствует компонент, который связывает их воедино: проходит по шагам плана, получает нужного провайдера, вызывает его и сохраняет результат.

Без этого компонента каждый новый тип выполнения требовал бы написания цикла вручную, дублируя логику обработки шагов, ошибок и логирования.

## Decision

Создан ExecutionPipeline — оркестратор выполнения. Он:

- не знает конкретных провайдеров — работает только через ProviderManager;
- не содержит условных переходов по типу провайдера (`if (provider === 'mcp')`);
- последовательно проходит по шагам ExecutionPlan;
- для каждого шага получает провайдера, проверяет его капабилити, вызывает `execute(step, context)`, сохраняет результат;
- ведёт журнал выполнения (executionLog) с метками времени, статусами и сообщениями;
- при ошибке на обязательном шаге (required: true) останавливает выполнение.

## Consequences

Положительные:
- единый механизм выполнения для всех типов задач;
- добавление нового провайдера не требует изменения pipeline;
- executionLog даёт полный аудит выполнения;
- pipeline не содержит бизнес-логики — только оркестрацию;
- возможность прервать выполнение на любом шаге без потери данных.

Возможные ограничения:
- pipeline не восстанавливается после падения процесса (будет добавлено позже через сериализацию ExecutionContext);
- последовательное выполнение — параллельное выполнение шагов может потребовать отдельного режима.
