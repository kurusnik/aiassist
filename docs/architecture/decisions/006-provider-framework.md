# ADR 006: Provider Framework

**Status:** Accepted

## Context

Programming Engine взаимодействует с множеством внешних сервисов: OpenRouter (LLM), MCP (данные РСВ), RAG (база знаний), файловая система (проекты). Без единого слоя абстракции код ядра будет содержать прямые импорты и вызовы каждого сервиса, что приведёт к жёсткой связанности и усложнит тестирование, замену и добавление новых интеграций.

## Decision

Все внешние интеграции проходят через Provider Framework — единый слой абстракции:

- **ProviderManager** — реестр провайдеров. Регистрация, поиск, получение по имени. Не содержит бизнес-логики.
- **BaseProvider** — базовый класс с полями `name`, `description`, `capabilities` и методом `execute()`.
- **Конкретные провайдеры** — наследуют BaseProvider, каждый отвечает за один внешний сервис.

Programming Engine не имеет прямых импортов внешних сервисов — только через ProviderManager.

## Consequences

Положительные:
- замена реализации провайдера не требует изменения кода ядра;
- новый провайдер добавляется регистрацией в ProviderManager;
- тестирование: любой провайдер можно замокать на уровне ProviderManager;
- единый контракт для всех внешних интеграций;
- возможность отключать провайдеров без изменения кода.

Возможные ограничения:
- дополнительный слой абстракции — незначительное увеличение сложности для простых случаев;
- метод `execute()` в BaseProvider должен быть достаточно обобщённым, чтобы подходить всем типам провайдеров.
