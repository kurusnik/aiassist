# ADR 005: План всегда строится до выполнения

**Status:** Accepted

## Context

Execution Planner (EP) отвечает за составление последовательности действий для выполнения задачи. Без явного разделения планирования и выполнения EP мог бы начать выполнять действия сразу после составления плана, что привело бы к смешению ответственности и усложнило логирование, анализ и модификацию плана.

## Decision

Execution Planner только составляет план (объект ExecutionPlan) и не выполняет его. Выполнение будет реализовано в отдельном компоненте, который принимает готовый план и последовательно вызывает провайдеров.

## Consequences

Положительные:
- план можно логировать и анализировать до выполнения;
- можно изменить план перед запуском (добавить/удалить шаги);
- простое тестирование: проверка плана не требует моков провайдеров;
- разделение ответственности: Planner думает, Executor делает.

Возможные ограничения:
- дополнительные 2-3 миллисекунды на построение плана перед выполнением;
- необходимость синхронизации формата данных между Planner и будущим Executor.
