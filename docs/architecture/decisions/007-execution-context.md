# ADR 007: ExecutionContext — единый контейнер состояния Pipeline

**Status:** Accepted

## Context

Pipeline Programming Engine состоит из последовательных этапов: Task Analyzer → Execution Planner → Context Collector → Prompt Builder → LLM → Reviewer → Result. Каждый этап производит данные (задачу, план, собранный контекст, промпт, результат). Без единого контейнера каждый этап должен был бы либо возвращать данные следующему через аргументы функции, либо хранить их в собственном состоянии, что приводит к жёсткой связанности этапов и усложняет добавление новых.

## Decision

Создан ExecutionContext — единый контейнер состояния выполнения. Он создаётся после Task Analyzer и Execution Planner, до начала работы провайдеров, и сопровождает задачу через весь pipeline.

ExecutionContext:
- не содержит бизнес-логики — только данные;
- предоставляет методы `setTask()`, `setPlan()`, `addData()`, `getData()`, `setPrompt()`, `setResult()`;
- хранит `collectedData` как словарь, где ключ — источник данных (metadata, examples, projectFiles, rag);
- сериализуется через `toJSON()`.

## Consequences

Положительные:
- любой этап pipeline может читать данные любого предыдущего этапа без изменения сигнатур функций;
- новый этап pipeline добавляется без изменения существующих — он просто читает и пишет в ExecutionContext;
- простое логирование и отладка: весь контекст можно сериализовать в JSON на любом этапе;
- ExecutionContext можно сохранить в БД для последующего анализа выполнения.

Возможные ограничения:
- риск "божественного объекта", если в контекст начнут складывать всё подряд — необходимо следить, чтобы контекст содержал только данные pipeline, а не временные переменные или настройки.

## Future Benefits

Благодаря полной сериализуемости ExecutionContext (`toJSON()` / `fromJSON()`) открываются следующие возможности:

- **Сохранение незавершённых задач.** Pipeline может быть прерван на любом этапе; ExecutionContext сериализуется и восстанавливается при продолжении.
- **Воспроизведение ошибок.** Если выполнение завершилось ошибкой, контекст фиксируется и может быть передан разработчику для анализа без повторного выполнения всех этапов.
- **Передача между агентами.** ExecutionContext может быть передан другому агенту (например, Reviewer получает контекст после LLM) без необходимости разделять память или общую БД.
- **Журнал выполнения Pipeline.** Каждый этап может сохранять копию контекста до и после своей работы, создавая полный аудит изменений состояния.
