# ADR 015: Reviewer Engine v1

**Status:** Accepted

## Context

После выполнения pipeline результат (ProgrammingResult) содержит код, но не проходит никакой проверки качества. Это означает:

- Код может отсутствовать, но success=true
- Код может не соответствовать языку задачи
- Код может игнорировать контекст запроса
- Отсутствует единая оценка результата

Необходим модуль, который выполняет лёгкую проверку результата **без LLM**, используя эвристики и синтаксические подсказки. Reviewer Engine — это не замена LLM-ревью, а быстрый фильтр на уровне pipeline.

## Decision

Созданы два новых класса:

### ProgrammingReview

Data-класс результата ревью:

| Поле | Тип | Назначение |
|------|-----|-----------|
| `passed` | boolean | Прошла ли проверка |
| `score` | number (0–100) | Оценка качества результата |
| `warnings` | string[] | Предупреждения (некритично) |
| `errors` | string[] | Ошибки (критично — passed=false) |
| `recommendations` | string[] | Рекомендации |

Поддерживает `toJSON()` и статический `fromJSON(data)` для сериализации, следуя конвенции ExecutionContext.

### Reviewer

Класс с единственным методом `review(context)` → ProgrammingReview.

#### Проверки

1. **Наличие кода.** Если code пуст или отсутствует — error, score -50.

2. **Проверка языка.** Если `task.language` известен — проверяет наличие характерных конструкций:
   - `bsl`: Процедура, Функция, КонецПроцедуры
   - `sql`: SELECT, INSERT, UPDATE, DELETE
   - `javascript`: function, const, class
   - `typescript`: interface, type, class
   - Если конструкция не найдена — warning, score -5.

3. **Семантическая проверка по запросу.** Если `task.originalRequest` содержит русские ключевые слова (сообщить, привет, таблица, форма, обработка, отчёт, документ, справочник, регистр, запрос, печать, создать, добавить, удалить, изменить, найти) — проверяет наличие похожих конструкций в коде через эвристики (вариации слов, английские аналоги). Без LLM, без NLP.

4. **Пустое explanation.** Если explanation отсутствует — warning, score -10.

#### Оценка (score)

Старт: 100. Вычитаются штрафы за ошибки и предупреждения. Результат клиппируется в 0–100. `passed=true` если нет критических ошибок.

#### Integration

Reviewer вызывается внутри InternalProvider в шаге `review_result`. Результат ревью сохраняется в `result.metadata.review` через `toJSON()`.

ProgrammingResult остаётся полностью обратно совместимым — добавляется только поле `metadata.review`, которое никак не влияет на существующую логику.

## Consequences

Положительные:
- Каждый результат pipeline теперь имеет числовую оценку качества
- Ошибки и предупреждения фиксируются для анализа
- Проверки работают без LLM — нулевая задержка
- ProgrammingResult остаётся обратно совместимым
- Reviewer не изменяет ExecutionContext, Pipeline, Task Analyzer

Ограничения:
- Эвристики не заменяют полноценное LLM-ревью
- Семантическая проверка работает только с русскоязычными запросами
- Набор конструкций для языков ограничен базовым

## Future Work

- Добавление проверок для других языков (python, java, go)
- Расширение набора эвристик для семантической проверки
- Опциональный шаг `ai_review` с использованием LLM для глубокой проверки
- Экспорт отчёта ревью в UI
