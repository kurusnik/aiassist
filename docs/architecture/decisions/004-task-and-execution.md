# ADR 004: Разделение Task и Execution

**Status:** Accepted

## Context

На начальном этапе ProgrammingTask содержал поля, описывающие как саму задачу (type, language), так и её выполнение (status, createdAt). Это приводило к смешению ответственности: один класс отвечал и за "что делать", и за "как идёт выполнение".

По мере развития Programming Engine появится Execution — сущность, которая описывает процесс выполнения задачи (статус, результат, ошибки, время).

## Decision

ProgrammingTask описывает только задачу:
- **id** — уникальный идентификатор задачи;
- **type** — тип задачи;
- **title** — заголовок;
- **language** — язык программирования;
- **domain** — предметная область;
- **originalRequest** — исходный запрос пользователя.

Поля выполнения (status, createdAt, result, errors) будут вынесены в отдельную сущность Execution, когда pipeline будет реализован. На текущем этапе Execution не реализуется, но код подготовлен так, чтобы его можно было добавить без изменения Task.

## Consequences

Положительные:
- Task описывает только "что" — чистый value object;
- Execution будет описывать "как" — lifecycle задачи;
- возможность выполнять одну задачу несколько раз (разные Execution для одной Task);
- упрощается тестирование: Task тестируется изоляцией от Execution.

Возможные ограничения:
- временно API не возвращает статус задачи (он будет добавлен вместе с Execution);
- небольшой рефакторинг потребуется при добавлении Execution.
