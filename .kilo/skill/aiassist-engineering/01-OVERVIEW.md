# AiAssist Engineering Skill — Overview

## Назначение проекта

AiAssist — персональная платформа интеллектуальных инструментов, а не просто чат с нейросетью. Это среда, в которой любые интеллектуальные задачи решаются одинаковым способом через единый жизненный цикл.

**Манифест (docs/AiAssist Manifesto v0.1.md):**
- Каждая задача проходит единый жизненный цикл: понимание → сбор контекста → план → получение информации → выбор модели → результат → проверка → сохранение знаний
- Любая новая возможность — новый Workflow, а не отдельное приложение (Programming, RAG, 1С, Research — всё Workflow)
- Новый модуль обязан использовать общее ядро платформы
- LLM — лишь один из источников интеллекта; ядро должно пережить смену любой технологии
- Каждый компонент существует в единственном экземпляре (один Provider Framework, один Prompt Builder, один Workflow Engine)
- Каждый этап работы должен быть воспроизводим, любой Workflow можно остановить, сохранить, продолжить, повторить
- Архитектура важнее скорости разработки
- Проект рассчитан на годы — каждое решение должно быть полезно через 3 года

## Ключевые принципы архитектуры

1. **Минимальная связанность** — каждый компонент знает о других ровно настолько, насколько необходимо
2. **Один слой — одна ответственность** — строгое разделение: Schema (DDL), Importer (ETL), Service (query), Context Builder (поиск + форматирование), Injection (вставка в промпт)
3. **Расширение без переписывания** — новая функциональность добавляется новым компонентом/методом, а не модификацией существующей логики
4. **MVP-first** — каждый спринт поставляет минимально работоспособную версию; упрощения фиксируются как roadmap, а не техдолг
5. **Правило двух кликов** — любая функция доступна максимум за два клика от главного экрана (ADR 002)
6. **Идемпотентность** — миграции и импорты можно повторять без ошибок
7. **Provider Framework** — все внешние интеграции только через ProviderManager; прямые импорты внешних сервисов в ядро запрещены (ADR 006)
8. **Project владеет данными** — ни один модуль не обращается напрямую к источникам; все данные через ProjectContextService (ADR 011)

## Технологический стек

| Компонент | Технология |
|-----------|-----------|
| Runtime | Node.js 18+ (CommonJS) |
| Framework | Express 5 |
| База данных | PostgreSQL 15 + pgvector |
| LLM | OpenRouter / LM Studio / OpenAI через LLM Aggregator |
| Embeddings | `@xenova/transformers` (Xenova/multilingual-e5-small, 384d) |
| OCR | Tesseract.js |
| MCP | JSON-RPC 2.0 поверх HTTP |
| Контейнеризация | Docker + Docker Compose |
| Прокси | Nginx + Certbot (SSL) |
