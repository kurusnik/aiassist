# Исправления для модуля изменения пароля

## Выполненные исправления

### 1. Упрощена валидация пароля
**Было:** Сложные требования к паролю (буквы разного регистра, цифры, специальные символы)
**Стало:** Только проверка длины (8-100 символов)

**Изменения в `services/passwordManager.js`:**
```javascript
static validatePassword(password) {
    const errors = [];
    
    if (!password || password.length < 8) {
        errors.push('Пароль должен содержать минимум 8 символов');
    }
    
    if (password.length > 100) {
        errors.push('Пароль не должен превышать 100 символов');
    }
    
    // Минимальная валидация - только проверка длины
    // Отключена сложная валидация по требованию пользователя
    
    return {
        valid: errors.length === 0,
        errors: errors
    };
}
```

### 2. Исправлены конфликты маршрутов
**Проблема:** Эндпоинт `GET /api/admin/users/:id/password-logs` конфликтовал с запросами
**Решение:** Добавлен эндпоинт `GET /api/admin/users/password-logs` (без ID) для получения всех логов

**Добавленные эндпоинты:**
- `GET /api/admin/users/password-logs` - все логи изменения паролей
- `GET /api/admin/users/:id/password-logs` - логи конкретного пользователя

### 3. Обновлен метод `getPasswordChangeLogs`
**Изменения:** Теперь метод принимает опциональный `userId`
```javascript
static async getPasswordChangeLogs(userId = null, limit = 50) {
    if (userId) {
        // Логи конкретного пользователя
    } else {
        // Все логи
    }
}
```

### 4. Добавлена отладочная информация
**В `services/passwordManager.js`:**
```javascript
static async verifyCurrentPassword(userId, currentPassword) {
    try {
        console.log('[DEBUG] Проверка пароля для userId:', userId);
        // ... остальной код
    }
}
```

**В `index.js`:**
```javascript
app.put('/api/change-password', requireAuth, async (req, res) => {
    try {
        console.log('[DEBUG] Изменение пароля: userId =', userId);
        console.log('[DEBUG] Сессия:', req.session);
        // ... остальной код
    }
});
```

## Текущие требования к паролю
1. **Минимальная длина:** 8 символов
2. **Максимальная длина:** 100 символов
3. **Другие требования:** Отключены по запросу пользователя

## API эндпоинты

### Для пользователей:
- `PUT /api/change-password` - изменить собственный пароль
  ```json
  {
    "currentPassword": "старый_пароль",
    "newPassword": "новый_пароль", 
    "confirmPassword": "новый_пароль"
  }
  ```

### Для администраторов:
- `PUT /api/admin/users/:id/change-password` - изменить пароль пользователя
- `GET /api/admin/users/password-logs` - все логи изменения паролей
- `GET /api/admin/users/:id/password-logs` - логи конкретного пользователя
- `GET /api/password-change/rate-limit` - проверка лимитов попыток

## Безопасность

### Сохраненные функции:
1. **Лимит попыток:** 5 попыток за 15 минут
2. **Логирование:** Все операции записываются в БД
3. **Хеширование:** bcrypt с солью
4. **Верификация:** Проверка текущего пароля перед изменением

### Отключенные функции:
1. **Сложная валидация:** Требования к символам отключены
2. **Проверка на простые пароли:** Отключена

## Дальнейшие действия

### Если проблема "пользователь не найден" сохраняется:
1. Проверить отладочные логи в консоли сервера
2. Убедиться, что пользователь авторизован (`req.session.userId`)
3. Проверить наличие пользователя в базе данных

### Для отладки:
1. Включить отладочный вывод в `PasswordManager.verifyCurrentPassword`
2. Проверить сессию пользователя
3. Проверить подключение к базе данных
