# Система выделения источников RAG

## 📊 Обзор

Система автоматически выделяет источники информации в ответах AI-ассистента:
- **📚 RAG источники** - информация из базы знаний проекта
- **📊 Анализ RAG** - выводы на основе информации из RAG  
- **💭 Знания модели** - собственные знания AI модели

## 🏷️ Синтаксис меток

### Основные метки:
1. `[RAG:SOURCE]` - начало цитаты из базы знаний
   ```text
   [RAG:SOURCE] Согласно документу API Guide... [/RAG]
   ```

2. `[RAG:ANALYSIS]` - начало анализа на основе RAG
   ```text
   [RAG:ANALYSIS] На основе документации... [/RAG]
   ```

3. `[MODEL:KNOWLEDGE]` - начало информации из знаний модели
   ```text
   [MODEL:KNOWLEDGE] Обычно такие API... [/MODEL]
   ```

4. Закрывающие метки:
   - `[/RAG]` - закрывает RAG:SOURCE или RAG:ANALYSIS
   - `[/MODEL]` - закрывает MODEL:KNOWLEDGE

### Примеры:

**Смешанный ответ:**
```text
[RAG:SOURCE] Документ говорит: "Все пользователи должны аутентифицироваться" [/RAG]
[MODEL:KNOWLEDGE] Для этого обычно используют JWT токены. [/MODEL]
[RAG:ANALYSIS] Значит, нужно реализовать систему токенов. [/RAG]
```

**Только RAG:**
```text
[RAG:SOURCE] PostgreSQL версии 14... [/RAG]
[RAG:SOURCE] Файл .env содержит конфигурацию... [/RAG]
```

**Только модель:**
```text
[MODEL:KNOWLEDGE] Это стандартная практика в разработке... [/MODEL]
```

## 🚀 Реализация

### Бэкенд (`services/rag/index.js`):
1. **`parseSourceMarkers(text)`** - парсит текст на сегменты
   - Возвращает массив сегментов с типами
   - Автоматически определяет источники

2. **`formatHighlightedResponse(parsed)`** - форматирует HTML
   - Добавляет CSS классы для подсветки
   - Включает иконки источников

3. **Обновленный system prompt** - инструктирует модель использовать метки

### Фронтенд (`public/app.js`):
1. **`parseResponseMarkers(text)`** - клиентский парсер
2. **`formatSegment(segment)`** - визуальное форматирование
3. **Автоматическая обработка** - при рендеринге чата

### Стили (`public/styles.css`):
- `.rag-source` - цитаты из RAG (синий)
- `.rag-analysis` - анализ RAG (зеленый)  
- `.model-knowledge` - знания модели (серый)

## 🔧 Использование в проекте

### 1. В существующем коде:
```javascript
const rag = require('./services/rag');

// Парсинг ответа
const parsed = rag.parseSourceMarkers(aiResponse);
console.log('Сегменты:', parsed.segments);

// Форматирование для фронтенда
const html = rag.formatHighlightedResponse(parsed);
```

### 2. В ответах AI:
Системный промпт автоматически инструктирует модель использовать метки. Модель должна:
- Обернуть цитаты из RAG в `[RAG:SOURCE]...[/RAG]`
- Собственные знания в `[MODEL:KNOWLEDGE]...[/MODEL]`
- Анализ в `[RAG:ANALYSIS]...[/RAG]`

### 3. На фронтенде:
```javascript
// Автоматически работает в renderChat()
// Для ручной обработки:
const segments = parseResponseMarkers(message.content);
const html = segments.map(formatSegment).join('');
```

## 📈 Преимущества

1. **Прозрачность** - пользователь видит, откуда взята информация
2. **Доверие** - четкое разделение источников повышает доверие
3. **Аналитика** - можно отслеживать использование RAG vs модели
4. **Обратная совместимость** - работает с ответами без меток
5. **Расширяемость** - можно добавить новые типы источников

## 🔄 Обратная совместимость

- Ответы без меток отображаются как `MODEL:KNOWLEDGE`
- Существующий код продолжает работать без изменений
- Можно постепенно внедрять метки

## 🚨 Ограничения

1. Модель должна соблюдать синтаксис меток
2. Неправильные метки могут нарушить парсинг
3. Не защищает от "галлюцинаций" модели, но делает их очевидными
